# RTDE Monitor requirements

Internal specification for the `rtde-monitor` URCap (`funh` / `rtde-monitor`). When a requirement changes, update this document in the same change and add a changelog row. If the implementation and this document disagree, make them match before the change is finished.

## REQ-1 Register operator screen

Application > Operator Screen lists one contribution, `funh-rtde-monitor-robot-monitor`, titled Robot Monitor. Selecting it opens the configuration presenter `funh-rtde-monitor-robot-monitor-config`. That presenter shows a segment selector in the center of the page. Its choices come from `MONITOR_PAGES` in `constant.ts`. The choices are Register and Robot Status. The label uses the system body font and primary text color. The selected segment uses the system active background, and that highlight slides to the newly selected segment. Register is selected when the operator screen is created, and the choice is stored in the operator screen parameters. The Operator Screen then shows that page. Register shows the general-purpose RTDE registers from the [RTDE Guide](https://docs.universal-robots.com/tutorials/communication-protocol-tutorials/rtde-guide.html). Values are subscribed as RTDE outputs, including registers that an external client writes as inputs.

| Section | Fields |
| --- | --- |
| `input_bit_registers` | `input_bit_registers0_to_31`, `input_bit_registers32_to_63`, shown as bits 0–63 |
| `input_bit_register_X` | `input_bit_register_64` … `input_bit_register_127` |
| `input_int_register_X` | `input_int_register_0` … `input_int_register_47` |
| `input_double_register_X` | `input_double_register_0` … `input_double_register_47` |
| `output_bit_registers` | `output_bit_registers0_to_31`, `output_bit_registers32_to_63`, shown as bits 0–63 |
| `output_bit_register_X` | `output_bit_register_64` … `output_bit_register_127` |
| `output_int_register_X` | `output_int_register_0` … `output_int_register_47` |
| `output_double_register_X` | `output_double_register_0` … `output_double_register_47` |

`output_int_register_X` is included because it is a register. It does not appear on the signals screen. A bit cell is on when the value is 1. Input registers on this screen stay read-only. Output registers can be written as described in REQ-5.

## REQ-2 Signal operator screen

Robot Status shows every RTDE controller output that is not a general-purpose register. Field names stay in the protocol spelling so they can be matched to the RTDE Guide. A field whose name ends in `_bits` is shown as a hexadecimal word. Clicking that value opens a square grid of its bits under the row, and clicking the value again hides the grid. Those cells are one quarter of the side length of a bit-register cell. The cell text is the bit index, starting at 0, and a lit cell is green. UINT32 words show bits 0–31. UINT64 words, including the digital input and output words, show bits 0–63. Fields whose names end in `_types` stay hexadecimal and do not open a grid. Sections are Joints, TCP, I/O, Safety and program, Tool, Payload and energy, and Controller. The filter matches the visible label and the protocol name.

Input-only RTDE fields that the controller does not publish as outputs, such as `speed_slider_mask` and `external_force_torque`, are out of scope.

## REQ-3 Backend subscription

The `rtde-monitor-backend` container connects to the controller RTDE interface at `urcontrol-rtde:30004`. The manifest grants the `urcontrol-rtde` service and the `urcontrol-secondary` service used by REQ-5. It exposes WebSocket ingress `websocket-api` on container port 52762.

- `/registers` streams REQ-1.
- `/signals` streams REQ-2.

The default sample rate is 20 Hz. `RTDE_HOST`, `RTDE_PORT`, and `RTDE_FREQUENCY` override the connection that starts with the process. Clicking the Hz label on a screen opens a wheel of integer rates from 5 Hz through 100 Hz. The new rate is applied only after Confirm, and only for the selected page: its RTDE subscription restarts at the chosen rate, and snapshots are pushed to that page at the same rate. Cancel leaves the current rate unchanged. The choice lasts until that page's last client disconnects, including when the configuration selects the other page. The next subscription starts from the default again.

`rtde-monitor-frontend/src/app/constant.ts` holds the product parameters used by the operator screens, including the frequency limits, the default, and the other timing and entry limits. Frontend code imports that file. The backend checks the same frequency limits in `rtde-monitor-backend/src/constants.py`.

A subscription starts when a page is selected and stops when that page's last client disconnects. If the controller rejects a field or a recipe is too large, the backend splits or drops that field, reports it as unavailable, and continues streaming the fields that were accepted. Controller exception text is shown as returned. It is not translated.

## REQ-4 Languages

UI chrome and section titles use ngx-translate. Files live in `rtde-monitor-frontend/src/assets/i18n/`. The file name is the PolyScope X language code:

| Language | File |
| --- | --- |
| English | `en.json` |
| Simplified Chinese | `zh-CN.json` |
| Traditional Chinese | `zh-TW.json` |
| Japanese | `ja.json` |
| Korean | `ko.json` |
| French | `fr.json` |
| German | `de.json` |
| Spanish | `es.json` |

`en` is the fallback language. Operator screen titles are the `operator-screen.<componentTagName>.title` entries, because PolyScope reads those keys. Protocol field names inside value cells stay untranslated. Each language file keeps the same keys. Keypad labels and write failures raised by this URCap are translated. Controller and script-interface errors are shown as returned.

## REQ-5 Output register writes

The Register page can change output registers. Input registers and the Robot Status page cannot.

| Control | Action |
| --- | --- |
| Output bit 0–127 | A click toggles the bit and sends `write_output_boolean_register(address, True\|False)` |
| Output integer 0–47 | A click opens the keypad. Confirm sends `write_output_integer_register`. The decimal key is disabled. The value must fit in a signed 32-bit integer |
| Output double 0–47 | The same keypad with the decimal key enabled. Confirm sends `write_output_float_register` |

The keypad is a three-column grid: digits 1–9, then sign, zero, and a decimal key, with delete beside the entry and cancel/confirm below. It does not open the system keyboard. The first digit replaces the current value. Confirm stays disabled until the entry is a complete number.

Writes go out as one secondary program on `urcontrol-secondary:30002`. `SCRIPT_HOST`, `SCRIPT_PORT`, and `SCRIPT_TIMEOUT` override that connection. The WebSocket command is `{ "op": "write", "id", "kind": "bit" \| "int" \| "double", "address", "value" }`. The reply is `{ "type": "write-result", "id", "ok", "error" }`. Only numbers produced by the keypad are inserted into the script. A running robot program can overwrite the same output register the next time it writes it. A successful reply means the secondary program was sent.

## REQ-6 Layout and zoom

Both pages use the same board. Switching the configuration keeps each page's own card order and scroll. The first row keeps the connection status on the left and the filter on the right. Focusing the filter opens the pendant's default alphanumeric keyboard, and a clear button inside the field removes the current text. Where the status line previously showed the RTDE host, the register screen shows Monitor - Register and the signals screen shows Monitor - Robot Status. The Live or Waiting word fades in and out at 0.3 Hz. Each RTDE section is a card. A card title uses the same warm header bar as a Variables section. Integer, double, and field signals are one full-width row, and those rows alternate white and light gray. Bit registers stay a grid of small cells. A lit cell is green. Signal names use the PolyScope body-medium size, the same size as a variable name, and wrap after an underscore instead of between letters. Values are bold. DOUBLE values, and each component of a VECTOR3D or VECTOR6D, are shown with 4 significant digits. That count is `DISPLAY_SIGNIFICANT_DIGITS` in `constant.ts`. A VECTOR6D component that is zero, or that rounds to zero at those 4 decimal places, is shown as `0.0000`. Vector components stay in a fixed two-column grid, and scalar values stay on one line, so a new sample does not change the row height. Integers, bit fields, and VECTOR6INT32 values stay exact. Every column is 300px wide on both pendant sizes. The board has eight columns and scrolls horizontally, not vertically. Columns 1 and 2 are the focus area: each holds one card in positions A1 and A2, stretched to the full height above the horizontal scrollbar with the same 12px gap used elsewhere on the page. Columns 3 through 8 each hold two positions, A3 and B3 through A8 and B8, and those two positions split the column height. An empty position shows its label. A card covers that label, and the card title does not repeat it. Empty positions stay visible so a card can be dragged into them. The board never grows past eight columns. A card body still scrolls internally when its own values do not fit the card.

Holding a card header lifts a copy of that card and the copy follows the pointer. Dropping it on another card swaps the two positions. Dropping it on an empty position moves the card there and leaves the previous position empty. A1 and A2 are the full-height positions. The order, the horizontal scroll position, and each card's vertical scroll for each screen are written to `/data/layout.json` in the backend container. An older file that stores only a list of ids, or only order and horizontal scroll, is still read; the next save stores `{ "order": [...], "scroll": n, "cards": { "joints": n } }`. `cards` maps a card id to that card body's scroll position. `order` lines up with A1, A2, A3, B3, A4, B4, and so on through B8. An empty string keeps that position vacant. The manifest mounts `persistent:/data`, so the file remains after a robot restart and after a URCap update. Reopening the screen restores the horizontal scroll and each card's own vertical scroll, instead of returning to the start. The bit grid under a `_bits` value stays hidden until that value is clicked. The reset icon at the right of the filter clears that screen's order, horizontal scroll, and card scrolls, and returns the cards to the default sequence at the start of the row. The icon is disabled while the cards are already in that sequence, the row is at the start, and every card is at the top. Filtering turns dragging off so a partial list cannot overwrite the saved order. Card bodies keep normal touch scrolling. Only the header captures the drag.

Sizes in the stylesheets are written in `px` and converted to `rem` at build time with `postcss-pxtorem` (`rootValue` 16), including the precompiled UI Design Library styles. `@media` breakpoints stay in `px`. `1px` borders stay in `px`. The URCap does not set the root font size, `--font-base-size`, CSS `zoom`, or `transform: scale()`. PolyScope X owns the zoom level. At 100% the layout matches the authored pixel sizes. On a TP7 at 135% the same `rem` sizes grow with the surrounding UI.

## Repository

`.gitignore` excludes dependencies, build output, IDE files, and Python caches so the project can be published without `node_modules`, `dist`, or `target`. Source, this specification, and the vendored RTDE Python client under `rtde-monitor-backend/src/rtde/` stay in the repository. That client keeps the Universal Robots copyright header.
